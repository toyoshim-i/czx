# SHARP X68000 (`msx68k`, Experimental)

`czx` includes an experimental SHARP X68000 target powered by [`toyoshim-i/msx68k`](https://github.com/toyoshim-i/msx68k) (Apache-2.0, compiled standalone as `msx68k_libretro.so` using `msx68k-bus` + `msx68k-vicon` headless EGL/GLES 2.0 with CPU fallback).

← [Back to README](../README.md)

| Item | Value |

## ROM Setup

Place your X68000 ROM dumps in `~/czx/roms/x68000/` (matched case-insensitively):

| File | Status | Purpose |
| :--- | :--- | :--- |
| `IPLROM.DAT` | **Required** *(for MC68000)* | X68000 IPL ROM (128 KiB) |
| `IPLROM30.DAT` | Optional *(required for `msx68k_cpu = 68030`)* | X68030 IPL ROM (falls back to `IPLROM.DAT`) |
| `CGROM.DAT` | **Required** | X68000 Character Generator ROM (768 KiB) |
| `SRAM.DAT` | Optional | Initial 16 KiB SRAM seed (if `~/czx/saves/msx68k_sram.dat` does not exist yet) |

If `IPLROM.DAT` or `CGROM.DAT` is missing, `czx` displays a **ROM FILES REQUIRED** screen listing `~/czx/roms/x68000/` and the missing files.

## Running & Dual-Drive Usage

```bash
# Auto-detects msx68k from .xdf / .dim / .hds / .hdf / .2dd (2x desktop window, auto-resizes on mode switch)
./build/czx /path/to/HUMAN302.XDF

# Start at 1x or 3x integer window scale (or switch live via Alt + 4/5/6)
./build/czx --scale 1 /path/to/HUMAN302.XDF

# Dual floppy boot (FDD 0 + FDD 1)
./build/czx /path/to/DISK_A.XDF /path/to/DISK_B.XDF

# SCSI HDD boot (or HDD + floppy)
./build/czx /path/to/SXWIN31.HDS
./build/czx --core msx68k /path/to/DISK_A.XDF --media2 /path/to/SXWIN31.HDS
```

- Floppy images in `FDD 0` and `FDD 1` can be hot-swapped or ejected anytime via `Alt + 8`.
- **Mouse**: On desktop Linux, mouse motion and left/right buttons inside the window are forwarded directly to the X68000 SCC mouse (`Alt + 7 → Mouse (FZXC)` is also supported).
- **Save Data**: Battery-backed SRAM is persisted at `~/czx/saves/msx68k_sram.dat`. SCSI HDD writes flush back to the mounted `.hds`/`.hdf`/`.img` file on unload/exit.

## Configuration (`~/czx/config/msx68k.cfg`)

Defaults seeded by `czx`:

```ini
msx68k_speed = 10      # 10 | 16 | 24 | 25 | burst
msx68k_cpu = 68000     # 68000 | 68030
msx68k_ram_mb = 4      # 4 | 2 | 1 | 6 | 8 | 12
msx68k_mode = compat   # compat | sx
msx68k_drive = FDD0    # FDD0 | FDD1 (active hot-swap slot)
msx68k_renderer = auto      # auto | gles2 | cpu (headless EGL+GLES2 with CPU fallback)
msx68k_gpu_scale = off      # off | fit_par | fit_4x3 | axis (managed automatically by czx on 320x170 LCD)
msx68k_opm_thread = offload # offload | inline | off (YM2151 OPM thread mode; MSX68K_OPM_THREAD overrides)
```

## Experimental Notes

- Video is rendered via `msx68k-vicon`'s `ViconCompositor` with headless EGL + OpenGL ES 2.0 (`libEGL.so.1` / `libGLESv2.so.2` loaded dynamically at runtime via `libloading` with dirty 4 KB VRAM page uploads) and automatic CPU fallback when EGL/GLES2 is unavailable.
- On the GLES 2.0 backend, the core uses double-buffered CPU/GPU frame pipelining (`submit_frame*` / `finish_frame_rgb565`), direct hardware `RGB565` readback when supported, and Pass 3 GPU downsampling (`msx68k_gpu_scale`) in `Aspect Fit` / `Axis Fit` LCD modes while keeping `1:1 Pan` and desktop modes at native resolution.
- Set `CZX_PERF_LOG=1` to log per-second pipelined frame timings (`cpu` / `finish` / `submit` / `aud`, plus `[opm_bg=... ev=... adpcm=...]` in `offload` mode) along with X68000 native CRTC resolution and refresh rate, or `CZX_PERF_LOG=detail` to also include synchronous `up` / `draw` / `rb` GPU breakdown.
- YM2151 OPM + MSM6258V ADPCM 62.5 kHz mixed stereo audio output is enabled and defaults to `msx68k_opm_thread = offload` (synthesizing OPM and ADPCM events on a dedicated background worker thread); `inline` and `off` are also supported and overridable via the `MSX68K_OPM_THREAD` environment variable.
- Building `msx68k_libretro.so` requires a Rust toolchain (`cargo` / `rustc`).
